# Durable account email outbox

Account verification and password-reset messages are written in the same database transaction as their token digests. The delivery payload is encrypted with Fernet using `EMAIL_OUTBOX_ENCRYPTION_KEY`; generate it with `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`. Store this key as a secret in each environment, back it up through the secret manager, and rotate only with an explicit re-encryption plan. Losing it makes queued messages unreadable.

The API does not send email inline. Run one or more `python -m apps.api.email_worker` processes against the same database. The worker claims account-action and priority-security-alert rows with database leases, sends via SMTP with STARTTLS, and retries transient failures with capped exponential backoff. It clears encrypted action payloads after delivery. A process crash after SMTP accepts a message but before the worker records success may cause a duplicate; account links remain single-use. Expired or consumed actions are not delivered. Priority alerts are only queued for verified, active organization owners/admins with alerts enabled, and eligibility is rechecked before sending.

Keep `APP_PUBLIC_URL` HTTPS in staging/production. Do not log message bodies, tokens, recipient addresses, or SMTP credentials. Monitor the count and age of pending/failed rows and worker health. Requeue failed action messages by issuing a fresh resend/reset request; do not manually expose token ciphertext. Priority alert messages omit URL path and query values.
